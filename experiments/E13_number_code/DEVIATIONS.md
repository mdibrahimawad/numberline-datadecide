# E13: deviations from METHODOLOGY.md / PLAN.md, and choices where they were unclear

Each entry says what the owner's text says, what the code does, and why.

| # | Topic | Owner's text | What the code does | Why |
|---|---|---|---|---|
| D1 | Layer indices | round(f·L) with f = 0, .125, .25, .375, .5, .625, .75, .84, 1 | int(f·L + 0.5) with f = 0.84375 instead of 0.84 | Reproduces the five old E10 layers exactly in all 9 models (check 2.5d). round() uses banker's rounding, and 0.84 gives layer 13 instead of the old 14 in 16-layer models. |
| D2 | All-layer average | mean over C2..C8 of P_num | mean over the 5 neutral contexts C2, C3, C4, C7, C8 | The owner's later instruction: neutral contexts for the main averaging; C5 and C6 are task contexts. The per-context files allow any other average at the 9 stored layers. |
| D3 | Within-context reliability | "agreement between two halves of the same context" | Added second wordings C2b–C8b (P_num only); C1's second set is the seed-7 copy prompts | With one prompt per number per context, a context has no halves. The second wordings give a within-context reference for M3, the distance agreement and the decomposition. |
| D4 | C1 seed-7 set | "a second set with seed 7" | The E10 format (A, B, C, D = random 1-, 2-, 3-, 4-digit numbers, never equal to n), generated by `prompts.c1_generated(7)` | The original E10 generator is not in the repo. Seed 42 uses the stored E10 prompts (`ref/c1_prompts_seed42.json.gz`), which are identical across models. |
| D5 | Controls in every test | full controls and planted power everywhere | FULL tier (all controls + planted power) for C1/P_next, C1/P_num and AVG5/P_num. LIGHT tier elsewhere (point estimates, shuffled n, digit-label shuffle, carry shuffle); LIGHT cells use the planted power of the FULL AVG5 cell with the same model, layer and set. | Compute: about 650 cells per model; the full planted checks cost ~1–3 CPU-min per cell. |
| D6 | S4 size | all numbers | M1, M2, M4, P8, H0 transfer and H3 reliability/frequency use the fixed 3,000-number S4 subsample (seed 0, as E12/E12c). H1, H2 and crowding use all S4 numbers. | Kernel CV cost. |
| D7 | Dev split | dev only for choosing layers, bandwidths, ranks, subspace sizes | The dev split is used for the causal choices (layer, m, α). Panel metrics use all numbers; bandwidths come from CV inside training folds. | Nothing is selected from the panel: every layer is reported. |
| D8 | M3 ceiling | "the same R² between halves" | The primary ceiling is split-half reliability tr Cov / √(trVar · trVar), Spearman–Brown corrected for AVG5. R²_half (using one half as the prediction of the other) is also reported. | R²_half understates the attainable R² (it counts both halves' noise). Reliability is the standard ceiling. |
| D9 | Sinusoidal probe | learned frequencies | Fixed base-10 periods {2, 5, 10, 100, 1000, 10000}, decoded jointly, plus a 25-period scan | Deterministic and fast; the scan shows whether another period dominates. |
| D10 | P8 "smooth k-dim latent model" | unspecified | Reduced-rank (rank k) regression on spline(n, df 10) + one-hot digits; knee and sharpness as in PREREG §3 | A concrete, testable version. k up to 30 is also reported, because the H1 expectation exceeds 10 for S3/S4. |
| D11 | H0 rule details | "≥ 3 of 7 natural contexts, same sign and ordering across models" | Cell rule + ≥ 70 % of cells; ordering = Spearman of model values > 0 | The owner gave no aggregation rule. |
| D12 | P7 pass rule | "score ≥ 0.75 plus a circular probe" | Score ≥ 0.75 at ≥ 3 of the 5 k values AND probe ≥ 0.5 | Avoids picking the best k. |
| D13 | Exponent probe | train {2, 3}, test 4 or 1 | Exactly that. 3-digit-group tokenizers (OLMo-2, Llama-3) have no single-token 4-digit numbers, so only length 1 is tested there. | Follows G1. |
| D14 | Causal details | "number-token positions"; patching between clean and corrupted number | Edits at the number's last token (where the subspaces are estimated). Ablation = mean-projection (h − QQᵀ(h − μ)). Patch source = the clean state of another test item with a different number. Behaviour metrics = log-prob margins (B1 larger vs smaller; B2/B3 true digit vs the best other digit; B4 n+1 vs n; B5 a+b vs the carry error ±10; B6 n vs n with the last digit +1). The decision rule is in difference form with bootstrap CIs. | Concrete definitions of what the plan leaves open. |
| D15 | Training stage | four emergence metrics; permutation test over metrics | Metrics: linear accuracy of the units digit, O1_leading, abs(e_1), H3 reliability. The permutation test runs within (layer, set) cells, because with 4 metrics a metric-level test can only reach p = 1/24. Spacing β is not recomputed (it is in the α/β paper). DataDecide uses the final ("main") revision. | Power of the test; scope. |
| D16 | Stop after each stage | stop, report, wait | `run_all.py` runs everything; Gate A is evaluated automatically and blocks the causal stage when it fails; all results are saved for review | The owner asked for one master script for the whole run. |
| D17 | Disk | keep files per context | Checkpoint and DataDecide vectors are deleted after a verified upload (results are kept). Main-model vectors are kept unless `--purge-main`. | 53 extra models × ~4 GB exceed a 100 GB volume. |
| D18 | dtype | bf16 for Qwen, fp16 for Pythia | float32 by default (TF32 off); `--dtype` can change it | Check (a) tolerance (2e-3) and check (d) cosine (0.999) are safest in fp32. Models ≤ 3B fit a 24 GB GPU in fp32. |
| D19 | Llama-3.2-1B | gated meta-llama repo | `unsloth/Llama-3.2-1B`, the mirror used for the old vectors; `--llama-id meta-llama/Llama-3.2-1B` switches | Check (d) compares with the old vectors from the mirror. StarCoderBase-3B is gated: the HF token's account must have accepted its licence. |
| D20 | Upload | upload each model's folder | Vectors are uploaded after extraction, `cells/` after analysis, and the report at the end; sizes are verified; the repo is refused if it is public | Analysis runs later than extraction. |
| D21 | Planted sizes | "at the real noise level" | Noise = real residual rows permuted. Planted sizes: M1 = the real f; M2 = the real digit part; H3 lexicon at true reliability 0.5; P8 = rank-3 of the real f + D; H1/H2 as in the Stage-1 pre-registration | The claimed structure at a size that should clearly pass. |
| D22 | Stage-1 code | n/a | `src/e13_stage1.py` gained optional switches (`n_rep=0` skips planted power, `n_ab`/`n_c` replicate counts); defaults are unchanged and the Stage-1 tests pass | Reuse. |
| D23 | Positions | offsets of the fast tokenizer | Exactly that. For OpenLLaMA (slow tokenizer in the old run) a prompt is flagged not-ok if the slow tokenizer gives different ids. | Offsets need a fast tokenizer. |
| D24 | Degenerate digit positions | n/a | If a digit position takes fewer than 4 values in a set (e.g. a sparse chunk-tokenizer set), its O1, PR and template are reported as missing and the cell fails the H1 rule | Otherwise the pair statistics are undefined (found in the checkpoint-runner test). |
| D25 | Layer 0 at a fixed token | n/a | Cells whose vectors are identical for every number (layer 0 at P_next / P_task) are recorded as "skipped" | They carry no information about n (found in the pilot). |
